# 拓竹（bambu-print）

多用户、群聊可用的 Bambu Lab（拓竹）3D 打印机控制扩展：看进度 / 已打印 / 剩余时间、暂停继续、停止、灯光、速度、温度，还能拍一张打印仓画面。

协议实现参照 [ClusterM/open-bamboo-networking](https://github.com/ClusterM/open-bamboo-networking)（下称 OBN）：

- **云端接口（默认，所有用户）**：Bambu 账号登录 → token → 云 MQTT（`u_<uid>`）看状态、控制。
- **本地接口（仅主人）**：打印机局域网 MQTT over TLS 8883，用户名 `bblp`，密码是打印机屏幕上的「局域网访问码」。
- **画面**：有局域网地址+访问码时优先走局域网（A1/P1 系列 :6000 MJPEG；X1/H2/P2S/X2D :322 RTSPS，需要 `ffmpeg`）；否则走云端 TUTK（见下）。

## 先说风险（请务必看完）

- **安全码是每个用户全部打印机秘密的唯一解密钥匙。** 服务端只存 scrypt 派生密钥加密后的密文；安全码本身不落盘、不进日志、不回显。**忘了只能清空这个用户的数据重绑**，找不回来。
- **访问码 / 云端 token 等同于打印机的控制权。** 谁拿到，谁就能暂停、停止、改温度、开灯，甚至发起打印。
- **只有主人一个高权限身份，没有「管理员」这一级；默认谁也看不到别人的 token。** 唯一的共享方式是**授权**：绑定者本人在私聊里把自己的 Bambu 凭据**限时共享**给某个 QQ（可选范围与时长），对方立刻就能查看/管理被授权的那几台打印机。没有授权码、没有兑换步骤，也没有任何「导出 token」的接口。
- **局域网模型只提供给主人。** 其他用户只能走云端账号登录；帮助、面板、命令里都不会出现局域网绑定的说明。
- **不要在任何群里发安全码、密码、访问码、授权码。** 这些操作只允许私聊；群里发会被直接拒绝。私聊里发安全码/访问码后机器人会尝试撤回，但**撤回可能失败**（超时、没权限），失败时请自己手动撤回。
- **局域网 TLS 用打印机自签名证书，分两条链路、保护强度不同。** 云端证书走系统 CA + 主机名校验；局域网是**先学后固定（TOFU）**：
  - **MQTT（8883，状态与控制）**：第一次连接只握手读证书、一个字节都不发；之后每次都用它当锚点 + 指纹严格校验。**没固定过证书就不发访问码**（直接失败并提示先固定），不会"先连上试试"。
  - **摄像头 MJPEG（6000）**：同样先学后用，**没锚点就拒绝抓拍**。
  - **RTSPS（322，X1/H2/P2S/X2D 的画面）**：这条链路 ffmpeg 无法做证书 pin，所以**不验证对端身份**——它要求"打印机所在局域网本机可信"这个前提。见下方「安全边界」一节。
- **云端画面（TUTK）需要一份 BambuSource 库。** 本模块不自己实现 DTLS/AV/H.264：它自带一个预编译的抓帧桥，在运行时加载 OBN 的 `BambuSource`（`src/camera/tutk/` 那套完整实现）。库没放好时会如实报错并给出下载地址，不会假装拍到了。

- **多用户模式开关**（默认开）：开着时每个 QQ 各绑各的打印机、互相看不到，别人可以用授权共享。**关掉就是单用户模式**——只服务主人一个人：其他人的命令、群聊消息、模型工具一律静默不响应（连「只给主人用」都不回，免得暴露这儿有个只服务主人的机器人）。适合只给自己用、不想让别人碰到的情况。
- **主人可以完全不设安全码（默认）。** 面板点一下「不用安全码，直接开启」就给主人建好账号，之后绑定 / 查状态 / 控制都不用再解锁。
  实现上不是把秘密存明文：主人的数据仍然是一把随机 DEK 加密的，只是**包这把 DEK 的钥匙从「你脑子里的安全码」换成了「这台机器上的 `host-key.bin`（32 字节随机，0600）」**。
  **代价**：能读到 `modules-data/bambu-print/` 这个目录的人（本机管理员、备份、同步盘）可以解开**主人**的绑定。
  其他用户不受影响：他们仍然各用各的安全码，互相看不到、主人也解不开。想更严一点，关掉设置里的「主人不用安全码」，主人就回到必须设安全码的旧行为。
- **局域网可以「发现」添加。** 面板点「搜索局域网打印机」，会向同网段发 SSDP 探测（UDP 2021，`ST: urn:bambulab-com:device:3dprinter:1`），列出机型 / 序列号 / IP / 名字，点一台自动填好序列号和 IP。
  **访问码不会广播** —— 那是拓竹刻意的安全设计，所以发现只能省掉「抄序列号和 IP」，访问码仍然必须从打印机屏幕上读出来手输。

## 多用户隔离怎么做

1. 每个 QQ 用户自己的打印机秘密，用**自己的安全码**派生密钥加密（scrypt → AES-256-GCM）。
2. 没有机器主密钥、没有「主人后门」：`vault.json` 只有密文和盐；拿到整份数据目录也解不开。
3. 解锁后密钥只留在进程内存，默认 **7 天**（可调 1~30 天）到期清零；`/打印机 锁定` 立即清。
4. 授权 = **按 QQ 限时共享凭据**：`grants.json` 里只有「谁授权给谁、哪几个绑定、什么范围、到什么时候」，没有秘密也没有可解密的密文。受权人操作时，秘密从**所有者的保险箱**里现解现用（所以所有者要保持解锁），撤销或到期立刻失效。
5. 面板接口只返回打码 QQ、掩码 token、打码序列号/IP；不存在查看明文的接口。
6. 错码计数持久化：连续错 5 次锁 15 分钟，到第 10 次锁 60 分钟。

## 权限层级

```
绑定 token 的用户（对自己绑定的打印机，含群内权限）
  > 模块设置（群模式、群拍照、群内显示文件名）
  > 主人（也要靠授权才能操作别人的）
```

- **准入跟着 Aurabot 自己的白名单走**：能跟她私聊的人 / 被她放进群白名单的群，才能用本模块；模块**不再单独维护私聊名单或群名单**（避免两处配置打架）。
- **私聊**：用户操作自己的打印机；对方授权后，直接就能操作被授权的打印机。
- **局域网 TLS 不跳过校验（MQTT 与 MJPEG）**：打印机用的是自签名证书，第一次连接自动学习并固定指纹，之后每次都用它当锚点严格校验；证书一变就拒绝，主人确认是自己换了固件后再 `/打印机 证书 信任`（这两个命令只给主人）。**没固定过证书时不会发送访问码**——不是"先连上试试"。RTSPS(:322) 画面链路是例外，见「安全边界」。
- **群聊**：群必须在 Aurabot 的群白名单里；提问者必须有绑定（或别人给他的授权）。全局群模式 `off` / `status` / `control`，但**绑定者本人可以覆盖自己那台**：私聊 `/打印机 群权限 只读|控制|关闭|跟随`，以及单独控制拍照、群内显示文件名。
- **群聊默认脱敏**：只显示进度、已打印 / 剩余时间、层数、温度；文件名显示「文件：已脱敏」，项目名永远不显示。只有绑定者本人、他自己开了「群内显示文件名」、模块设置也允许时才显示文件名。
- **绑定 / 解绑 / 登录 / 安全码 / 授权 / 接口 / 群权限**：只允许私聊。

## 用 Bambu 账号登录（和 ha-bambulab 的流程一致）

```
/打印机 登录 <账号> <密码>          # 账号是邮箱或手机号
/打印机 验证码                       # 云端要求验证码时：先请求发送
/打印机 验证码 <6位>                 # 再提交
/打印机 两步验证 <6位>               # 云端要求 2FA 时用
```

- 账号用 **OAuth（Google / Apple 等）注册**的，要先在 Bambu 手机 App 里设置密码（Account Security → Change Password），之后才能用账号+密码登录。
- 登录会话只放内存 5 分钟；密码只用于这一次登录，成功后 token 加密进该用户自己的保险箱，密码不保存。
- 登录成功后自动拉取账号下的打印机（一个 token 可以对应多台）。

### 聊天里的「/打印机 帮助」用合并转发

命令太多，一次刷几十行群里会被折叠，所以帮助用**合并转发**发：**一次就把所有页塞进同一张折叠卡片**，翻页不用再发消息。

实现上按会话类型选接口：`send_group_forward_msg`（群）、`send_private_forward_msg`（私聊），都不行再试通用的 `send_forward_msg`；三个都失败会退回分页纯文本（用 `/打印机 帮助 2` 仍可指定页）。

- **多台打印机又没指定时，也是合并转发**：`/打印机 状态`、暂停、拍照等命令遇到「你有多台打印机」时，会用一个折叠卡片列出每一台（编号 + 名字 + 型号 + 打码序列号），点开就能挑。发不出去才退回纯文本清单，回复编号照样能选。

| 页 | 内容 |
|---|---|
| 1 | **风险告知**：访问码等同控制权、别发群里、局域网会固定并核对身份 |
| 2 | **数据存储策略**：加密存在本机 `modules-data/bambu-print/`、每人一把独立密钥、主人免码的代价、解锁到期即清 |
| 3 | **看状态与简单控制**：状态 / 暂停 / 继续 / 停止 / 灯 / 速度 / 温度 / 拍照 |
| 4 | **登录云端账号**：登录 / 验证码 / 两步验证 / 同步 |
| 5 | **列表、授权、群权限**：列表 / 授权 / 撤销 / 审计 / 群权限 |
| 6 | **安全码与解锁**：设置安全码 / 解锁 / 锁定 / 改安全码 |
| 7 | 主人专用（局域网绑定、证书）—— 只有主人有这一页 |

每条命令下面带一行说明：参数含义、默认值、以及前提（比如「停止必须私聊」「温度 0 表示关加热」「授权默认 30 分钟只给看状态」）。每页 6~15 行。
合并转发里按顺序就是第 1~7 页；退回纯文本时用 `/打印机 帮助 2` 翻页，页号超出范围会夹到首尾。

**只有主人额外可用**（局域网）：`/打印机 绑定 本地 …`、`/打印机 绑定 追加 …`、`/打印机 解绑 <编号>`、`/打印机 接口 云端|本地|自动`。其他用户的帮助里不会出现这些。

多台打印机而没指定时，会列编号并等你回「1」「第二台」；10 分钟内（可调）不用重复选。

也可以直接对她说话，比如「打印机还剩多久」「暂停一下打印」，她会用 `bambu_printer` 工具处理；群里默认只能查状态。

## 云端画面（TUTK）

Bambu 云端实时画面走 ThroughTek Kalay（IOTC/AV）P2P：云端铸 `ttcode` → 云端向打印机推 `liveview.prepare` → 打印机打开 TUTK 服务端 → 客户端用 DTLS-PSK + AV 会话取 H.264。Node 的 TLS 不支持 DTLS，纯 JS 解 H.264 也不现实，所以：

1. 模块用该打印机所属用户的云端 token 调 `POST /v1/iot-service/api/user/ttcode` 铸凭据（`lib/tutk.mjs`）；
2. 把 `bambu:///tutk?…` URL 写进一个 **0600 临时文件**（绝不放进命令行参数，进程列表看不到）；
3. 交给**模块自带的抓帧桥** `assets/tutk-bridge/bambu-tutk-bridge`（已预编译，纯 C，**不需要 .NET / Node / npm**）；
   桥在运行时动态加载 `BambuSource`（OBN 的库），调同一套 `Bambu_*` C ABI；
4. 样本是 MJPEG 就直接用；是 H.264 Annex-B 就交给本机 `ffmpeg` 解一帧 JPEG；
5. 清理临时文件（含 URL 文件与样本）。

**BambuSource 从哪来**：本模块**不打包**它（OBN 是 AGPL-3.0），但面板里有一个
**「下载 BambuSource 库」按钮**，点一下就会自动完成：

1. 查 OBN 最新 Release（查不到就用已知版本 v2.3.0）；
2. 下载 `obn-windows-x64.zip`（Windows）/ `obn-linux-x64.tar.gz`（Linux）；
3. **只解出**压缩包里那一个库文件（`lib/v02.09.01/BambuSource.dll` 或 `lib/libBambuSource.so`），
   别的不落地；
4. 放到桥程序同目录（`modules/bambu-print/assets/tutk-bridge/`），桥下次启动自动找到。

**国内网络**：按钮会按你本机时区/语言判断。国内优先走 GitHub 加速代理
（`githubproxy.cc` → `ghfast.top` → `ghproxy.net` → `gh-proxy.com`），全都失败再回退直连；
国外先直连、失败才用代理。下载用的是 HTTP Range 分段读取，所以**只拉需要的那几 MB**，
实测国内走代理约 5 秒完成（不是整包 88MB）。

也可以完全手动：

| 平台 | 下载 | 取哪个文件 |
|---|---|---|
| Windows x64 | `obn-windows-x64.zip` | `lib/v02.09.01/BambuSource.dll` |
| Linux x64 | `obn-linux-x64.tar.gz` | `lib/libBambuSource.so` |

把库放到桥同目录即可；或者在面板「设置 → BambuSource 库路径」填绝对路径，或用环境变量 `BAMBU_SOURCE_LIB`。

面板里还有「检查 TUTK 组件」按钮：会分开告诉你桥有没有、库有没有，缺哪个说哪个。

**桥要不要自己编译**：不用——仓库里已经带了 Windows x64 与 Linux x64 的预编译产物。
其它架构（Linux aarch64 / macOS）按 [assets/tutk-bridge/README.md](assets/tutk-bridge/README.md)
用 `cc` / `gcc` / `zig cc` 重编（仍然不需要 .NET）。

前提：打印机已绑定云端、账号有云画面权限、打印机开机联网。铸码后的服务窗口大约 9 分钟，过期要重新铸。

## 面板

一个面板（「平台」分组下），页内分四个页签：

| 页签 | 谁用 | 做什么 |
|---|---|---|
| **总览** | 只读 | 谁绑了、绑了什么、几台、最近是否解锁（序列号打码，不含 token） |
| **局域网绑定** | 只有主人 | 搜索局域网自动填序列号 / IP，补上访问码即可；绑完直接试连一次 |
| **设置** | 主人配置 | 群模式、接口与时长、云端画面组件 |
| **审计** | 只读 | 每次解锁 / 绑定 / 控制 / 授权各一行，操作者显示完整 QQ |
| **帮助** | 只读 | 风险告知、本地安全策略、命令速查 |

- **页首的风险提示是一条横幅，不是常驻大卡**：只有一句「访问码等于打印机控制权，别发到群里」，点「我知道」就收起来，之后重开面板也不再出现（记在本机 localStorage）。完整四条风险告知和本地安全策略在「帮助」页。

- **总开关只有一个位置**：页面顶部卡片右上角。它写的是设置项 `active`，和左侧「拓竹」入口标签上的小圆点是同一个值——开关一保存，入口指示灯就跟着变。关掉后机器人不再响应任何打印机命令，也不会去连打印机。
- **设置改动只进草稿**：改完点页面底部的「保存设置」才生效（和「表情包」「B 站」那些内置页一致）；面板自己不再画第二个保存按钮，也**不会**在改动的瞬间偷偷落盘。
- **校验规则由服务端一份规则表驱动**：面板从 `/overview` 拿到 `rules`（每项的上下界、默认值、可选值、说明），输入框的 min/max、失焦夹取、提示文字全部来自这同一份规则；服务端在保存时再按同一份表归一化一次。所以「按钮上写的」和「实际生效的」不会两样。
- **局域网绑定是主人专属的**：它只在这个面板里、且只有解锁主人之后才可用；普通用户看不到也用不了，命令帮助里也不会出现。

**面板本身也拿不到明文 token**：解锁只是让服务端在内存里有该用户的密钥，接口永远不会返回访问码/token 明文；访问码输入框是 password 型，提交成功后立刻清空。

## 会访问哪些地址

模块只连下面这些地方，没有别的出站请求。除了「BambuSource 下载」那一段是你主动点按钮才会发生，其余都是你发命令 / 开面板时按需连接。

| 地址 | 什么时候连 | 传什么 |
|---|---|---|
| `api.bambulab.com`、`api.bambulab.cn` | 你用 Bambu 账号登录、同步设备、铸 TUTK 凭据 | 你的 Bambu 账号密码（仅登录那一次）、token |
| `us.mqtt.bambulab.com`、`eu.mqtt.bambulab.com`、`cn.mqtt.bambulab.com`（8883） | 走云端接口看状态 / 控制 | 该用户的云端 token |
| 打印机局域网 IP（8883 MQTT / 6000 MJPEG / 322 RTSPS） | 主人绑定局域网后 | 局域网访问码；画面走本机 `ffmpeg` |
| 同网段 UDP 2021（SSDP） | 面板点「搜索局域网打印机」 | 只有一个发现请求，不带凭据 |
| 打印机所在局域网内的 TUTK P2P | 走云端画面抓帧 | 云端铸的 ttcode（经 0600 临时文件交给桥） |
| `api.github.com`、`github.com`、`codeload.github.com` | 只有你点「下载 BambuSource 库」 | 一个匿名 GET，不带你的任何账号信息 |
| `githubproxy.cc`、`ghfast.top`、`ghproxy.net`、`gh-proxy.com` | 同上，但只在你本机判断为国内网络、或直连失败时 | 同上；请求的是 GitHub 的同一个文件 URL |

关于下载这一条要说明白：它**不是**在无人值守时偷偷拉东西。必须由主人/用户在面板上点那个按钮才会发生，下载内容是 OBN 发布的 `BambuSource` 库文件（`BambuSource.dll` / `libBambuSource.so`），落盘位置是模块自己的 `assets/tutk-bridge/` 目录。模块自带的抓帧桥会在运行时 `LoadLibrary` / `dlopen` 这个库。不想要这条链路可以完全不点这个按钮——局域网画面和所有控制功能都不依赖它。

## 设置项与生效时机

下面这张表就是服务端 `lib/settings.mjs` 里的规则表：默认值、上下界、可选值三者同时决定「面板上能填什么」「保存时怎么夹」「运行时不合法怎么回落」。面板从 `/overview.rules` 读同一份表，所以不会出现「按钮说 1~30、实际能存 999」这种偏差。

| 设置项 | 类型 | 默认 | 范围 / 可选值 |
|---|---|---|---|
| `active` | 开关 | 关 | 总开关；入口标签小圆点读的就是它 |
| `groupMode` | 单选 | `status` | `off` / `status` / `control` |
| `groupPhoto` | 开关 | 开 | 群里能不能要画面 |
| `allowGroupName` | 开关 | 关 | 群里是否显示文件名 |
| `defaultInterface` | 单选 | `cloud` | `cloud` / `lan` |
| `ownerInterface` | 单选 | 跟随默认 | `''` / `cloud` / `lan` |
| `ownerLocalAllowed` | 开关 | 开 | 主人能不能用本地接口 |
| `unlockDays` | 整数 | 7 | 1~30 天 |
| `maxBindings` | 整数 | 5 | 1~20 条 |
| `requestTimeoutMs` | 整数 | 6000 | 2000~20000 毫秒 |
| `selectedTtlMinutes` | 整数 | 10 | 1~60 分钟 |
| `tutkBridgePath` | 文本 | 空 | 留空用模块自带的桥 |
| `tutkLibPath` | 文本 | 空 | 留空在桥旁边自动找 |
| `tutkTimeoutMs` | 整数 | 20000 | 3000~60000 毫秒 |

生效时机：**点页面底部「保存设置」那一刻**一次性落盘并立即生效（解锁有效期在每次解锁前再同步一次保险箱，不用重启模块）。启动时还会做两件事：把 `active` 对齐成真实开关状态（老版本只存过 `enabled`），以及把历史遗留的越界值按上表归一化一次，之后磁盘上的值就是实际生效的值。

## 安全边界（哪些地方真正验证了对端身份）

这套模块连三种对端，保护强度**不一样**，别混为一谈：

| 链路 | 端口 | 对端身份校验 | 凭据什么时候发 |
|---|---|---|---|
| 云端 MQTT | 8883 | **系统 CA + 主机名校验**（Node 默认，从不覆盖） | 校验通过后 |
| 局域网 MQTT | 8883 | **TOFU 锚点 + 指纹固定**（首次只握手读证书） | 固定过证书之后；没固定就失败，不发访问码 |
| 局域网 MJPEG | 6000 | **TOFU 锚点**（同上） | 有锚点才发认证包；没锚点直接拒绝抓拍 |
| RTSPS | 322 | **启动 ffmpeg 前先比对指纹**（不一致就不启动） | 指纹核对通过后 |
| 云端 TUTK | — | 云端铸码 + 本机抓帧桥 | 凭据经 0600 临时文件交给桥 |

**RTSPS 与其它三条的做法不同**：ffmpeg 的 RTSP 输入不接受自定义 CA / 指纹 pin，所以模块把校验**放在启动 ffmpeg 之前**——先对 `host:322` 握手取证书，和固定过的指纹比对，不一致就直接失败，**ffmpeg 根本不会启动**（访问码不会进 stdin，更不会出现在 argv）。首次抓 X1 系列画面时自动固定一次，`/打印机 证书` 里能看到「画面（322）」那一行。但仍有前提：

- 它**要求「打印机所在的局域网本身可信」**——这是它唯一的前提。
- 同一局域网里如果有人能做主动中间人（ARP 欺骗 + 伪造 :322 服务），这条链路可能把访问码交给对方，或者让你看到伪造画面。
- MQTT(:8883) 与 MJPEG(:6000) **不受这个影响**：它们有锚点校验，冒充端会握手失败或指纹不匹配。
- 只关心进度、暂停、温度这些的日常使用完全不经过 RTSPS；RTSPS 只在「要一张 X1/H2/P2S/X2D 的画面」时用到。

**TOFU 的固有边界**：局域网首次连接会信任当时遇到的证书。如果首次连接那一刻就已经存在主动中间人，恶意证书会被固定。要彻底排除只能带外核对指纹——私聊发 `/打印机 证书` 能看到当前指纹，和打印机屏幕上 / 你信任的渠道核对一致即可。

## 数据与隐私

- 数据在 `modules-data/bambu-print/`：`vault.json`（用户与加密绑定）、`grants.json`（授权密文）、`audit.jsonl`（操作记录，不含秘密）。
- 文件 0600、目录 0700、原子写；审计只记动作与结果，不记 token / 安全码 / 文件名。
- 卸载模块不会自动删数据；要彻底清除请删这个目录。删了就**无法恢复**，需要重新登录/绑定。

## 已知限制

- 只支持 MQTT 控制面（暂停/继续/停止/灯/温度/速度）与拍照；切片、上传文件、发起打印不在本模块范围（用 Bambu Studio / Orca）。
- X1 / H2 / P2S / X2D 的画面是 H.264，需要本机 `ffmpeg`。
- 云端画面需要一份 BambuSource 库（OBN 产物；抓帧桥本身已随模块预编译）+ ffmpeg（H.264 机型）；库没放好时只有带局域网地址+访问码的打印机拍得了。
- 局域网 TLS 是「先学后固定」而不是跳过校验：MQTT(8883) 与摄像头 MJPEG(6000) 没固定证书就**拒绝发送访问码**。
- **RTSPS(322) 的画面链路**会在启动 ffmpeg 前核对 :322 的证书指纹（不一致就不启动），但首次固定仍是 TOFU 语义。
- 「剩余时间」来自打印机自己的估算（`mc_remaining_time`）；打印机没给时显示「剩余时间未知」，不编。
